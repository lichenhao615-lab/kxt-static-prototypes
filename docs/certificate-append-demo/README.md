# 德国 WEEE 追加与续费交互 Demo

## 续费 Demo（2026-11-10）

- 文件：`renewal.html`、`renewal.css`、`renewal.js`；直接打开 `renewal.html`。
- 决策：先选择续费商品，再按需确认注销费用；没有注销商品直接进入支付。
- 参考：用户最新三张截图，分别为规格选择弹窗、后台续费列表、续费订单支付抽屉。
- 保留后台淡青导航、续费列表行内入口、居中弹窗、右侧订单抽屉；属于基于截图的交互优化，不声称 1:1 复刻。
- 独立于客户端追加页，不改业务代码，不调用真实接口，不更新飞书文档。
- 本次仅开放续费相关路径；相邻的“添加备注”禁用，其他业务导航作为页面背景保留。

### 路径与规则

| 场景 | 路径 |
| --- | --- |
| 全部续费 | 列表“续费” → 选择续费商品 → 支付 |
| 部分不续费 | 列表“续费” → 选择续费商品 → 确认注销费用 → 支付 |
| 全部不续费 | 选择页取消全选 → 确认全部商品注销费用 → 支付 |
| 返回修改 | 保留勾选、发票信息和支付方式；重新计算续费与注销费用 |
| 取消 / 关闭 | 未支付内容不生效；重新进入恢复默认选择 |
| 支付成功 | 本地保存订单；列表可回看，刷新后保留，防止重复提交 |

- 不续费商品按注销处理；付款不会立即生成注销服务单。
- 注销生成时间按对应商品关联服务单自身的区间结束时间计算。
- 例如区间结束日期为 `2026-12-31`，最早 `2027-01-01 00:00:00 +08:00` 生成。
- 第二行公司特设不同结束日期：一项增值服务到 `2026-12-31`，一项追加服务到 `2027-12-31`；用于验证注销依据各自区间。相关基础单假设已覆盖这些年度。
- 示例支付时间固定为 `2026-11-10`；所有注销服务单均尚未生成，不模拟后台定时任务。

### Demo 假设

- 默认全选续费，减少漏选；用户可逐项取消或取消全选。
- 全不续费暂按全部商品注销处理，使用相同确认与支付路径。
- 金额全部为预置示例：两项续费分别 ¥2,600、¥1,800，注销每项 ¥1,000；不定义新的定价、优惠或支付规则。
- 为展示金额核对，注销费用暂与续费费用同页汇总并模拟支付；实收时点及现有支付规则仍以业务实现为准。
- 保留截图五种支付方式，统一只做本地模拟；不开启真实扫码或转账。
- 发票默认“否”，选择“是”展示抬头与纳税人识别号，并校验是否填写。
- 本地存储键：`kxt-certificate-renewal-demo-v1`，与追加订单分离。

- 以用户 2026-11-11 最新口径为准：先选择追加商品，再填写类目和品牌。
- 保留跨信通系统布局、青绿色主色及追加弹窗。
- 基础服务覆盖年份作为入参匹配商品；商品名称和覆盖年份同时展示。

- 验证单年/跨年商品、逐年报价与独立服务区间。
- 为交互优化示例，不作 1:1 复刻声明，不调用业务接口。

## 工作台与资料复用（2026-11-11）

- 默认进入工作台，“快捷入口”新增“追加服务”，点击后打开追加指引。
- 指引支持按公司名称搜索，并按国家、类目筛选可追加基础服务。
- 指引先展示可追加的基础服务，选单后进入追加页；原基础服务列表行内入口继续保留。
- 证书类追加带入基础服务的类目和品牌；增值服务按自身资料要求复用基础服务单资料。
- 修改只保存到本次订单及后续服务单，不回写基础服务单。
- 追加页显示“已带入基础服务单类目与品牌”和“来自基础服务单”。

## 已确认规则

- 主入口：工作台 → 快捷入口 → 追加服务 → 追加指引 → 选择基础服务单。
- 兼容入口：基础服务列表的行内“更多操作 → 追加商品”；基础服务已支付且有效。
- 基础服务区间年份作为入参查找商品；商品初始不选中。
- 基础商品带入行展示具体品牌；基础品牌只读，仅选择新增品牌数量。
- 新增类目行选择品牌数量，不填写具体品牌名称。
- 选择品牌数量后提示：提交追加后，请在服务单上传资料时补充具体品牌信息。
- 基础区间为 2026～2027 时，返回 2027 年商品和 2026～2027 年商品。
- 商品卡展示商品名称、覆盖年份、服务区间、在售状态和费用。
- 商品覆盖年份即追加服务年份，不再单独选择年份。
- `2026+2027` 作为一个商品一次性计价，不拆分年度价格；服务区间仍分年记录。
- 追加仅填写类目和品牌；产品名称、重量、销量、链接、图片、尺寸不在追加页重复填写。
- 品牌支持多选、搜索及新增；可清空、取消勾选，同一行可关联多个品牌。
- 按各产品类型、品牌和年度校验已购及待支付冲突，所选品牌去重后汇总年度示例报价。
- 类目表头及填写标签旁提供说明文档下载，不打开新页面或影响当前填写。
- 同一基础、类目、品牌、年度不能重复购买。
- 不生成跨页面草稿；取消后重新进入恢复空白。
- 订单有效支付后才生成追加服务单，按所购年度独立保存服务区间。
- 追加页不修改续费及注销页面；真实业务实现不在本次 Demo 范围。

## 布局选择

首页展示工作台快捷入口；也可从基础服务列表通过“更多操作 → 追加商品”进入。弹窗采用“商品选择 + 类目品牌清单”：商品决定匹配年份和报价，类目品牌清单用于定位、增删和校验。

右侧固定展示商品覆盖的年度、区间及示例费用；窄屏改为上下排列。首次进入弹窗时商品不选中，类目和品牌从基础服务单带入。

## 示例数据边界

- 示例基础单覆盖 2026、2027 年，仅返回符合这两个年度的在售商品。
- 示例商品为 2027 年单年商品与 2026～2027 年跨年商品；不推断其他年份的历史补购窗口。
- 基础已有“屏幕设备 / KXT”注册；选择相同组合与年度会拦截。
- “灯具”2027 年为停售样本，用于验证阻断提示。
- 展示金额为本地预置报价，用于验证年度拆分及去重，不代表实际价格或新的计价公式。
- 同类目、同品牌组合禁止重复；多个品牌分别计入报价。
- 当前年度服务开始时间使用示例支付日 2026-11-10；未来年度使用 1 月 1 日。实际生效起点仍以现有业务规则为准。
- 支付及订单保存在当前浏览器 localStorage 中，便于回看和防止重复操作；未提交表单不保存。

## 使用

直接打开 `index.html`，无需服务端。

完整路径：工作台 → 追加服务 → 选择基础服务 → 选择追加商品 → 核对/填写类目品牌 → 核对年度费用 → 提交 → 确认订单 → 模拟支付 → 查看追加服务及独立区间。

弹窗关闭后可以从“追加商品”重新进入。待支付订单可以继续支付，已支付订单回看只读服务区间。
